# EventVivid 电子票额度销售方案

> 版本：V1.0  
> 日期：2026-09-23  
> 适用范围：活动平台的新租户获客与电子票额度销售；额度模式已确认，金额仍为试运营参考价。

## 1. 销售主张

EventVivid 按**成功签发的电子票张数**收费。客户可免费创建活动、配置票种和报名表；新租户获赠电子票额度，用完后可购买补充。赠送和购买的额度进入同一个租户余额，均可跨活动使用。一个活动办多少人、一个租户办多少场，均不再由固定年费套餐限制。每次消耗多少额度、剩余多少额度必须可查询、可对账。

原开发文档中的“免费版／标准版／高级版一年服务期、会议次数上限、单场报名人数上限”已被电子票额度模式替代。现有租户已获得的存量合同权益按原有效期保留，不自动缩减或转换；首次迁移时另获赠 100 张电子票额度，历史出票不追溯扣费。

| 商品 | 电子票额度 | 建议售价 | 折合单张 | 获取方式 |
| --- | ---: | ---: | ---: | --- |
| 新租户赠送 | 100 张 | ¥0 | ¥0 | 注册自动发放，每租户一次 |
| 小额补充包 | 100 张 | ¥99 | ¥0.99 | 在线购买 |
| 常用包 | 500 张 | ¥399 | 约 ¥0.80 | 在线购买 |
| 批量包 | 2000 张 | ¥1399 | 约 ¥0.70 | 在线购买 |
| 大客户方案 | 10000 张起 | 单独报价 | 合同约定 | 销售签约、后台发放 |

- 额度属于租户，可分配给其名下任意活动；不限定单场活动人数或年度活动数量。票种本身的库存及活动报名截止时间仍然有效。
- 报名收费与票种售价无关：免费票、付费票均消耗 1 张额度。支付渠道手续费和短信发送费用单独披露，不从票券额度中暗扣。
- 所有电子票额度均不设使用期限，赠送与购买额度的消耗、返还规则完全相同；系统不维护“体验余额”和“已购余额”。流水保留发放来源、订单和操作人等信息，仅用于对账与审计。
- 不对自助客户开放透支。经过授信的签约客户可选择按月后付，按成功出票量结算；后付单价、授信额度和账期写入合同。自助版先实现预付额度。

## 3. 计费口径

**1 张已签发、可供入场的电子票 = 消耗 1 张额度。** 一笔订单购买 3 张票，成功签发后消耗 3 张。报名人数、订单数、二维码查看次数和验签次数都不单独计费。

| 场景 | 额度处理 |
| --- | --- |
| 创建活动、发布活动、配置票种或报名表 | 不消耗 |
| 提交付费订单但尚未支付 | 预留相应额度；支付失败或超时自动释放 |
| 免费报名确认，或付费订单支付成功并出票 | 从预留额度转为实际消耗 |
| 重试支付回调、刷新电子票、补发同一票码或重复验签 | 不重复消耗 |
| 活动开始前，票券未验签且全额取消／退款 | 票券作废后返还相应额度一次 |
| 活动已开始、票券已验签或仅部分退款 | 不自动返还额度；异常由总部人工处理并留审计记录 |
| 整场活动取消 | 未验签票券作废；符合退款条件的已消耗额度返还，已预留额度释放 |

同一张票的“预留、消耗、返还”必须使用唯一业务键和幂等处理。额度流水只追加记录，不直接改写历史；任意时点的余额 = 所有额度入账（赠送、购买、人工补发）+ 返还 − 出票消耗 − 退款冲减。实际可用余额还应扣除未完成订单的预留额度，不允许为负数。

## 4. 余额不足与续购体验

1. 活动平台显示“可用额度、已预留、累计消耗、本月消耗”和最近流水；公开价格页展示额度包、单价和估算器。
2. 可用额度低于 50 张时提示租户管理员；低于 10 张时在工作台、活动报名管理页突出提醒，并允许从提示直接购买。
3. 报名提交前原子预留足够额度。余额不足时不创建可支付订单；公开报名页提示“名额暂不可用，请联系主办方”，活动平台向管理员提示具体缺口与充值入口。
4. 余额归零后，已有报名、订单、电子票和现场验签正常使用；补充额度后，新报名自动恢复。
5. 购买成功后立即增加额度并生成可查询的充值流水；支付回调重复投递不得重复发放。需要退款的未使用预付额度按适用规则和购买协议处理。

## 5. 数据留存与附加服务

按量模式没有统一的“一年服务到期日”。所有活动数据均从**活动结束时间**起统一留存 **6 个月**，与电子票额度的获取方式无关。留存到期前通知管理员导出；到期后的处置需遵循平台数据处理规则。

短信、品牌定制和专属支持可以作为独立增值服务，不改变统一的 6 个月数据留存期。MVP 先销售电子票额度，避免价格页同时出现过多难以解释的收费项。

## 6. 页面与后台需求

- **公开首页及价格页**：说明“注册赠送 100 张电子票额度，成功出票才扣额度”；展示额度包单价、适用场景、出票与退款口径、购买入口和常见问题。人数估算器输入预计出票量，显示需要补充的额度及可选商品。
- **注册与活动平台**：新租户自动获得 100 张电子票额度；工作台展示统一余额。“额度与账单”页查看余额及逐笔流水，支持选择 100/500/2000 张额度包、订单确认、PC 微信扫码和手机收银台。正式收款使用官方 Go SDK 对接汇付斗拱 `T_JSAPI`，产品号 `XLSISV`。未配齐密钥、公众号和公网 HTTPS 时只创建待支付订单供核对，不发起交易或发放额度；支付开放后须经服务端验签查单确认再幂等入账。当前仍需完成真实支付联调和退款/日对账后再正式上线，期间可联系客服，由总部人工补发。
- **总部后台**：维护额度商品与生效价格；查询租户余额、预留、消耗、充值和返还流水；支持有权限的人工赠送或冲正，并要求原因和审计记录。
- **服务端**：出票前校验额度并原子预留；支付结果驱动消耗或释放；退款与活动取消驱动合规返还。所有操作以 `tenant_id` 隔离，支付回调和人工操作均需幂等。

## 7. 分阶段上线与验证指标

1. **内测**：只发注册赠送额度并记录出票量，检验出票、退款、重复回调和并发报名的计费口径。
2. **试运营**：开放 100／500／2000 张充值包及自助购买，邀请不同规模的主办方验证建议价格。
3. **稳定期**：加入低余额自动补充及签约客户月结。

重点观察：注册到首场发布转化率、赠送的 100 张额度用尽后的首购率、各额度包销量、每租户月出票量、余额不足导致的报名中断率，以及扣除短信、支付和服务成本后的毛利。依据这些数据调整包容量和价格。
