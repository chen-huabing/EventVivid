> 文档版本：V1.3
> 对应 PRD：EventVivid PRD V1.3
> 目标读者：产品、交互、前端、后端、测试、运维  
> 更新日期：2026-09-30
> 本次新增：网站备案、微信应用注册、平台服务商申请及租户特约商户进件方案；这些规划不代表支付能力已上线。

## 1. 开发目标

MVP 必须以四个独立应用交付，打通以下完整业务闭环：

```text
总部开通租户
  → 租户登录活动平台
  → 创建活动与票种
  → 发布公开报名页
  → 参会人报名并支付
  → 系统生成电子票
  → 工作人员登录验签页
  → 首次验签成功 / 重复验签拦截
  → 活动平台与总部查看统计和审计
```

## 2. 系统组成与部署

### 2.1 独立应用

| 应用包 | 建议本地端口 | 目标域名示例 | 登录体系 | 主要设备 |
| --- | ---: | --- | --- | --- |
| `apps/hq-web` | 5174 | `hq.eventvivid.com` | 平台管理员账号 | 桌面端 |
| `apps/organizer-web` | 5173 | `console.eventvivid.com` | 租户成员账号 | 桌面端/平板 |
| `apps/attendee-web` | 5175 | `m.eventvivid.com` | 手机号验证码或匿名会话 | 移动端 |
| `apps/checkin-web` | 5176 | `checkin.eventvivid.com` | 现场工作人员账号 | 手机/手持设备 |
| `apps/api` | 3000 | `api.eventvivid.com` | JWT、公开访问令牌、幂等键 | 服务端 |
| `apps/worker` | 无 HTTP 端口 | 内部服务 | RabbitMQ 凭证 | 服务端 |

当前代码库已实现 `hq-web`，活动平台、报名页和验签页暂位于 `apps/web` 的不同路由中。MVP 收口前应按上表拆为三个独立构建与部署单元，共享 `packages/ui`、`packages/contracts` 和 `packages/api-client`。

### 2.2 技术栈

- 后端：Node.js 20 LTS、TypeScript strict、NestJS、Fastify。
- Web：React、Vite、React Router。
- 数据库：PostgreSQL，Kysely 作为类型安全访问层，复杂库存逻辑允许原生 SQL。
- 缓存：Redis，用于验证码、限流、短期会话和热点查询。
- 消息：RabbitMQ Quorum Queue，用于通知、支付后处理、导出和 Webhook。
- 文件：S3 兼容对象存储，用于封面、报名附件和导出文件。
- 测试：Vitest、Supertest、Playwright。
- 可观测性：结构化日志、OpenTelemetry、Prometheus、Grafana、Loki。

## 3. 公共开发规范

### 3.1 身份与会话

- 总部账号与租户账号分表、分签发者、分登录入口，不共享登录态。
- 总部 JWT 建议 8 小时过期；租户后台访问令牌建议 2 小时并配刷新令牌。
- 报名页允许匿名浏览；查询个人订单时必须手机号验证码验证。
- 验签员必须被授权到活动或验签点，令牌中不得直接信任前端传入的活动范围。
- 密码使用 bcrypt/Argon2 哈希，不记录明文，不在日志中输出 Token。

### 3.2 多租户隔离

- 所有租户业务表必须包含 `tenant_id`。
- 服务层从已验证会话获取租户，不接受客户端任意指定 `tenant_id`。
- 核心查询必须显式附加租户条件；条件缺失视为代码缺陷。
- 总部接口使用 `/hq/*` 命名空间和独立 Guard。
- 租户停用或到期后，禁止写业务数据；查询与续费能力按策略保留。

### 3.3 API 约定

```json
{
  "data": {},
  "requestId": "req_01..."
}
```

错误响应：

```json
{
  "code": "TICKET_SOLD_OUT",
  "message": "该票种已售罄",
  "requestId": "req_01...",
  "details": []
}
```

- 报名、支付确认、退款和验签必须携带 `Idempotency-Key`。
- 分页统一使用 `page`、`pageSize`；列表返回 `items` 和 `total`。
- 时间统一以 ISO 8601 UTC 传输，界面按活动时区展示。
- 金额字段统一以 `amountCents` 表示整数分。

### 3.4 通用页面状态

每个数据页必须提供：

1. 首次加载骨架屏。
2. 空状态及下一步操作。
3. 网络错误和重试入口。
4. 无权限状态。
5. 会话过期后保存当前地址并跳转登录。
6. 表单提交中的禁用和防重复提交。
7. 成功提示、业务错误和字段级错误。

## 4. 应用一：总部后台

### 4.1 用户与边界

总部后台只服务 EventVivid 平台内部人员。任何租户成员均不能登录或调用总部接口。

### 4.2 页面结构

```text
/login                 总部登录
/                      平台总览
/tenants               租户管理
/tenants/:id           租户详情
/credits               电子票额度与账本
/channels              支付渠道
/risk                  风控中心
/audit                 审计日志
/settings              平台设置
```

### 4.3 登录页 `/login`

功能：

- 管理员账号、密码登录。
- 登录中按钮禁用，失败时显示统一错误，避免泄漏账号是否存在。
- 成功后保存短期 Token，跳转原目标页面或总览。
- 连续失败触发 IP 与账号维度限流。
- 登录成功、失败、退出均产生安全日志。

操作流程：

1. 输入账号和密码。
2. 前端校验非空和最小长度。
3. 调用 `POST /api/v1/hq/auth/login`。
4. 后端验证账号状态和密码哈希。
5. 签发总部 Token，更新最后登录时间并记录来源 IP。
6. 前端请求 `GET /api/v1/hq/auth/me` 恢复会话。

### 4.4 平台总览 `/`

展示：

- 租户总数、正常/停用/到期数量。
- 活动总数、今日新增活动。
- 订单总数、已支付金额、退款金额。
- 累计验签、今日验签和重复验签。
- API、数据库、消息队列、支付回调健康状态。
- 最近风险事件和总部操作。

操作：

- 时间范围切换：今日、近 7 日、近 30 日。
- 点击指标跳转对应列表并自动带筛选条件。
- 数据异常时展示最后更新时间和重试入口。

### 4.5 租户管理 `/tenants`

列表字段：租户名称、租户 ID、活动数、电子票可用额度、服务状态、存量合同有效期、开通时间、操作。

功能：

- 按名称搜索；按状态和余额区间筛选。
- 新建租户，默认状态为正常、有效期为永久或由总部指定。
- 重命名租户。
- 设置具体到期日、续期 30 天、续期一年、设为永久有效。
- 停用与恢复；停用前二次确认并说明影响。
- 到期状态：永久有效、正常、30 天内到期、已到期。
- 所有变化写入 `platform_audit_logs`，记录变更前后值。

租户管理流程：

1. 点击“开通新租户”，填写企业或组织名称。
2. `POST /api/v1/hq/tenants` 创建独立数据空间。
3. 列表刷新并展示永久有效状态。
4. 点击“管理”打开租户弹窗。
5. 修改名称或期限，调用 `PATCH /api/v1/hq/tenants/:id`。
6. 停用/恢复调用 `PATCH /api/v1/hq/tenants/:id/status`。
7. 后端在同一事务内更新租户并写审计日志。

### 4.6 租户详情 `/tenants/:id`

标签页：

- 概览：电子票余额、预留额度、存量合同有效期、成员、活动、交易和存储用量。
- 成员：租户管理员列表、邀请状态、最近登录。
- 额度：统一电子票余额、逐笔发放／消耗／返还流水；短信量和文件存储单独展示。
- 活动收款配置：显示租户特约商户进件、签约、AppID 绑定和支付权限状态及脱敏商户信息；总部按权限协助处理进件驳回和诊断，不收集租户商户密钥。服务商申请和进件设计见 13.5～13.7。
- 操作记录：该租户相关的总部审计日志。

### 4.7 电子票额度 `/credits`

- 按租户查询统一余额、已预留、可用额度和最近 100 笔流水。
- 新租户注册或总部开通时一次性赠送 100 张；赠送与购买的电子票额度类型相同，均不设使用期限。
- 总部超级管理员和财务可按租户人工补发额度，必须填写原因、幂等流水号，并记录平台审计；人工补发不是收款成功。
- 额度包为 100、500、2000 张，服务端定价分别为 99、399、1399 元。租户管理员选择额度包、确认商品后生成待支付订单，PC 展示微信扫码入口。参数未配齐时可以核对订单，但不能调用支付或发放额度。
- 存量套餐数据仅作兼容，不用于新租户开通或新销售。

### 4.8 平台支付渠道 `/channels`

本页面只管理 EventVivid 自身的收款渠道，用于销售电子票额度补充包。额度购买指定使用汇付斗拱聚合支付的[聚合正扫接口](https://paas.huifu.com/docs/api/#/smzf/api_jhzs)，微信内支付场景使用 `trade_type=T_JSAPI`。渠道商 `sys_id=6666000244121044`、平台收款商户 `huifu_id=6666000245068152`、产品号 `product_id=XLSISV`；这些标识通过服务端环境配置，不写入浏览器代码。它与租户为活动收款绑定的支付商户完全分离。

- 接入前还须配置请求签名私钥与响应验签公钥、已与该商户绑定的微信服务号 AppID 和支付授权目录、公网 HTTPS 异步通知地址。`T_JSAPI` 下单使用用户在对应 AppID 下经真实微信授权取得的 OpenID，不得伪造或复用其他公众号的 OpenID。
- PC 活动平台展示订单与手机付款二维码，二维码指向本平台短期有效的手机收银台地址；租户使用微信扫码，在手机微信内完成授权和 `T_JSAPI` 支付，PC 页面查询服务端订单状态。二维码是付款网页入口，不是微信 Native 支付的 `code_url`；桌面浏览器不能直接调起 JSAPI。域名、AppID 与跨端订单令牌要求见 13.3、13.4、13.7。
- 平台保存租户额度购买订单、请求日期/流水号、汇付交易流水与终态；金额和额度包价格由服务端决定，不能信任浏览器传入金额。下单受理和前端支付回调均不发额度。异步通知由官方 SDK 对原始 `resp_data` 验签，持久化后响应 `RECV_ORD_ID_请求流水号`；后台补偿任务独立查单。只有经 SDK 验签的查询结果同时匹配商户、订单号、日期、金额、交易类型且 `trans_stat=S`，才在同一事务内更新订单、额度流水和余额，回调丢失也可以查单补偿，重复通知不得重复发放。
- 支付状态需支持待支付、处理中、已支付、失败/关闭和退款；处理回调丢失、查单补偿、退款和对账。付款页面返回时只展示待确认状态，不依据前端结果直接显示支付成功。
- 平台商户收取电子票额度补充包的款项；租户活动的报名款不得进入平台商户账户。
- 密钥通过部署环境的 Secret Manager 或等效密钥系统注入；总部页面只显示已配置状态和脱敏标识。敏感值仅允许轮换，不允许明文回显、复制或写入普通日志和审计详情。
- 保存或轮换前验证配置格式与渠道连通性；轮换、启停、回调地址变更均须二次确认并写高风险审计。
- 渠道停用前提示受影响的额度订单与未完成支付；停用只阻止新支付，不得丢失已有支付或退款回调处理能力。
- 当前已实现官方 Go SDK 适配、额度订单、PC 扫码入口、手机微信 OAuth/JSAPI、通知验签、查单补偿和幂等入账；默认关闭真实支付。提供公钥不等于已完成收款配置，还需配对的服务商私钥、获批绑定的服务号 AppID/AppSecret、公网 HTTPS 域名，并完成真实沙箱/生产联调。退款、日对账及主动关单暂未实现，不得宣称支付功能已正式上线。总部人工补发仍是独立操作，不能伪装成支付成功。部署和测试要求见[汇付 SDK 支付接入](汇付SDK支付接入.md)。

### 4.9 总部支付配置边界

- 总部可查看租户的支付渠道类型、绑定状态、商户号脱敏值、最近验证/回调状态和错误摘要，用于支持诊断。
- 总部不得代租户收集商户私钥、APIv3 密钥、证书文件或要求租户通过微信、邮件、工单发送这些凭据。
- 服务商模式下，租户通过活动平台授权提交营业执照、经营资料、结算账户等进件信息，并由租户法定代表人/经营者或获授权超级管理员完成微信核验和签约；总部只有获授权的进件运营人员可协助核对必要资料。进件资料与商户密钥是不同的数据类别，按 13.6 的访问和留存规则管理。
- 总部可以配置平台自己的收款商户，用于 EventVivid 收取电子票额度补充包费用；该配置不可被活动订单复用。
- 平台服务商 API 私钥、APIv3 密钥及公众号 AppSecret 只在服务端密钥系统中管理；总部普通客服和租户均不可读取。租户不需要提供自己的 APIv3 密钥或 API 证书。

### 4.10 风控中心 `/risk`

- 指标：登录失败、异常支付、库存冲突、重复验签、退款失败。
- 风险事件列表支持等级、类型、租户和时间筛选。
- 事件详情展示请求链路、关联订单、处置记录。
- 支持标记已处理、误报和转人工。

### 4.11 审计日志 `/audit`

- 字段：时间、操作人、角色、动作、对象、来源 IP、结果和追踪 ID。
- 支持按操作人、动作、对象类型和时间筛选。
- 日志只读，普通管理员无删除权限。
- 导出任务异步执行并生成带水印文件。

### 4.12 总部后台 MVP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/hq/auth/login` | 总部登录 |
| GET | `/hq/auth/me` | 当前总部用户 |
| GET | `/hq/dashboard` | 平台总览指标 |
| GET/POST | `/hq/tenants` | 查询或创建租户 |
| PATCH | `/hq/tenants/:id` | 重命名与有效期管理 |
| PATCH | `/hq/tenants/:id/status` | 停用或恢复 |
| GET/POST | `/hq/tenants/:id/credits` | 查询租户额度／人工补发额度 |
| GET | `/hq/audit-logs` | 审计日志 |

## 5. 应用二：活动管理平台

### 5.1 用户与边界

网站公开区域面向潜在客户，介绍 EventVivid 产品与电子票额度；登录后的工作区域服务租户内部团队。用户登录后只能访问所属租户及被授权的活动。

### 5.2 页面结构

```text
/                              产品首页（公开）
/pricing                       价格页（公开）
/login                         租户登录（保留现有登录表单及注册、找回密码入口）
/dashboard                     工作台（需登录）
/events                        活动列表
/events/new                    创建活动
/events/:id/overview           活动概览
/events/:id/basic              基础信息
/events/:id/tickets            票种与库存
/events/:id/forms              报名表
/events/:id/registrations      报名管理
/events/:id/orders             订单与退款
/events/:id/tickets-issued     已出票列表
/events/:id/notifications      通知中心
/events/:id/checkin            现场管理
/events/:id/reports            活动报表
/members                       团队与权限
/credits                       额度与账单
/settings                      租户设置
/settings/payment              支付设置（租户活动收款）
```

未登录用户可访问 `/`、`/pricing`、`/login`。访问工作区域时跳转 `/login`，登录成功后返回原目标地址；已登录用户仍可浏览产品首页和价格页。原工作台 `/` 的导航目标调整为 `/dashboard`，站内菜单、登录成功跳转和退出登录跳转同步更新。

### 5.3 产品首页 `/`

首页用于介绍产品能力并引导了解电子票额度、注册和登录，桌面端优先，同时适配手机浏览。

- 顶部导航：EventVivid 标识、产品功能、价格、登录、免费注册；“产品功能”跳转本页功能区，“价格”进入 `/pricing`。
- 首屏：一句话说明“活动发布、报名售票、现场验签集中管理”，展示“免费注册”和“查看价格”两个主要操作。
- 功能区按实际业务流程展示：活动创建与发布、票种与库存、可配置报名表、报名与订单、电子票二维码、现场验签、活动数据报表及团队权限。每项包含简短说明，不承诺尚未上线的能力。
- 流程区展示“创建活动 → 发布报名页 → 参会人报名 → 获取电子票 → 工作人员验签 → 查看统计”。
- 页脚提供价格、登录和产品联系入口；首页不展示租户业务数据。
- 点击“免费注册”进入现有登录页的注册状态；点击“登录”进入 `/login`，保持现有登录表单和找回密码功能。

### 5.4 价格页 `/pricing`

价格页公开展示“注册赠送 100 张电子票额度”和 100／500／2000 张补充包。人民币价格在试运营确认前标注为参考价，不开放虚假的在线付款按钮。

| 商品 | 额度 | 试运营参考价 |
| --- | ---: | ---: |
| 新租户赠送 | 100 张 | ¥0 |
| 小额补充包 | 100 张 | ¥99 |
| 常用包 | 500 张 | ¥399 |
| 批量包 | 2000 张 | ¥1399 |

- 所有额度汇入同一余额，赠送和购买没有不同有效期或消耗优先级；流水仅记录来源用于审计。单张成功出票扣 1 张，免费票和付费票一致。
- 不设置年度活动数量或单场报名人数套餐上限，仍须遵守票种库存、售票时间和活动发布状态。
- 所有活动数据从活动结束起统一留存 6 个月，不因余额归零或额度来源不同而改变。
- 充值支付渠道上线前，补充包仅提供联系开通入口；总部可人工发放额度并记录原因，但不得把人工发放显示为线上购买。

### 5.5 租户登录 `/login`

- 支持账号密码；后续扩展手机号验证码和企业 SSO。
- 登录时校验租户状态；仅存量合同租户继续受原有效期约束，新额度制租户没有服务到期日。
- 停用显示“服务已暂停”；到期显示到期时间和管理员联系方式。
- 登录后加载租户、角色、活动授权和功能开关。

### 5.6 工作台 `/dashboard`

- 指标：进行中活动、今日报名、今日收入、待审核、待退款。
- 近期活动卡片展示时间、报名进度、收入和发布状态。
- 待办区域聚合审核、退款、库存告警和通知失败。
- 快捷操作：创建活动、导入名单、进入现场看板。
- 展示电子票可用额度、预留额度；余额低于 50 张提示，低于 10 张突出提醒。

### 5.7 活动列表 `/events`

字段：封面、名称、时间、地点、状态、报名数、出票数、验签数、负责人。

操作：

- 搜索和按状态、时间、负责人筛选。
- 新建、复制、预览、发布、取消、结束。
- 草稿可删除；已产生订单的活动只允许取消，不物理删除。
- 复制活动默认不复制订单、人员和验签记录。

### 5.8 创建活动 `/events/new`

采用分步向导：

1. 基本信息：名称、短链接、封面、主办方、类型和描述。
2. 时间地点：时区、开始结束时间、线上/线下地点。
3. 票种：名称、价格、库存、售卖时间、限购规则。
4. 报名表：字段、实名、审核和隐私授权。
5. 交易规则：选择已在租户支付设置中启用的收款渠道、订单超时、退款规则、发票说明。活动不能自行收集或保存商户密钥。
6. 预览发布：移动端预览和发布校验。

保存规则：

- 每一步自动保存草稿。
- 短链接唯一，输入时异步校验。
- 结束时间必须晚于开始时间。
- 至少存在一个有效票种才能发布。

### 5.9 活动概览 `/events/:id/overview`

- 报名漏斗：访问、选票、提交、支付、出票。
- 交易：订单、收入、退款和客单价。
- 现场：出票、已验签、未验签、重复票。
- 分享：报名链接、二维码、复制和渠道参数。
- 活动关键配置缺失时显示待办提示。

### 5.10 票种与库存 `/events/:id/tickets`

- 新建和编辑票种：名称、说明、价格、容量、售卖时间。
- 上下架、排序、复制票种。
- 显示总库存、锁定、已售、可售和退款释放数量。
- 已产生订单后，价格修改仅影响新订单并记录版本。
- 减少库存不得低于已售和已锁定数量。

### 5.11 报名表 `/events/:id/forms`

- 系统字段：姓名、手机号、邮箱、证件号、公司、职位。
- 自定义字段：单行、多行、单选、多选、下拉、日期、附件。
- 支持必填、提示语、选项、显示条件和字段排序。
- 展示隐私政策与用途说明。
- 发布后修改字段需要提示对已有报名和导出的影响。

### 5.12 报名管理 `/events/:id/registrations`

- 字段：报名人、联系方式、票种、报名状态、订单状态、来源、时间。
- 搜索姓名、手机号、订单号或票码。
- 批量审核、取消、导入和导出。
- 查看报名详情、表单答案、订单、票券、通知和操作记录。
- 导出手机号、证件号等敏感数据需要权限和水印。

### 5.13 订单与退款 `/events/:id/orders`

- 字段：订单号、报名人、票种、原价、优惠、实付、状态和支付时间。
- 支持关闭待支付订单、发起全额退款、查看渠道退款结果。
- 退款前展示票券状态、验签状态和退款规则。
- 已验签订单默认禁止自动退款，需要高级权限人工处理。
- 支付与退款回调支持重试和人工补单，但禁止直接修改金额。

### 5.14 付费报名

当前代码允许选择付费票并提交报名，创建待支付订单、锁定票种库存和电子票额度，展示票种、金额及微信支付按钮；真实支付渠道尚未接入，点击支付提示主办方尚未配置微信支付，不把订单确认或前端返回当作付款成功，也不签发付费电子票。免费票仍可确认报名并出票。

目标方案为 EventVivid 申请普通微信支付服务商，协助租户进件成为特约商户，参会人在微信内使用 JSAPI 支付，微信将款项结算到该租户的结算账户。平台不代收活动报名款，租户不提交 API 密钥。此方案需在业务模式、主体资质和微信审核通过后实施，详见 13.5～13.7。

支付设置 `/settings/payment` 规划为“活动收款开通”：租户管理员填写进件资料、查看驳回项与申请进度、扫码完成官方核验和签约、查看收款商户及开通结果；不提供租户 API 密钥输入框。尚未实现该功能时，不把示例资料或总部人工标记展示为已开通支付。

### 5.15 通知中心 `/events/:id/notifications`

- 模板：报名提交、审核通过、支付成功、出票、活动变更、退款结果。
- 支持站内、短信、邮件和微信模板消息渠道。
- 显示发送中、成功、失败和退订状态。
- 失败任务支持单条重发和批量重试。

### 5.16 现场管理 `/events/:id/checkin`

- 创建验签点，配置活动、场次、票种和允许次数。
- 创建工作人员并授权验签点。
- 生成工作人员登录二维码或一次性邀请码。
- 实时看板展示验签速度、累计入场、入口分布和失败原因。
- 验签记录支持查询、导出和有权限的撤销。

### 5.17 活动报表 `/events/:id/reports`

- 报名趋势、票种构成、来源渠道、支付转化。
- 收入、退款、优惠和支付渠道对账。
- 验签率、时段分布、入口分布和失败原因。
- 报表口径必须排除无效订单并明确时间范围。

### 5.18 活动平台核心流程

新租户进入活动平台：

```text
产品首页 → 价格页了解电子票额度 → 免费注册 → 获赠 100 张额度 → 登录工作台
```

发布活动：

```text
创建草稿 → 填基础信息 → 配票种 → 配报名表 → 配交易规则
→ 发布校验 → 预览 → 确认发布 → 生成报名链接和二维码
```

处理退款：

```text
订单详情 → 检查退款规则与票券状态 → 确认退款金额
→ 创建退款单 → 支付渠道处理 → 回调更新订单和票券 → 通知参会人
```

## 6. 应用三：参会人报名页面

### 6.1 设计原则

- 移动端优先，关键按钮单手可达。
- 未登录即可浏览，最晚在订单查询时完成手机号验证。
- 页面不暴露租户后台或内部 ID。
- 网络中断时保留已填写表单，恢复后可继续。

### 6.2 页面结构

```text
/e/:slug                 活动详情
/e/:slug/tickets         选择票种
/e/:slug/form            填写报名
/e/:slug/confirm         确认订单
/pay/:orderNo            支付
/pay/:orderNo/result     支付结果
/ticket/:code            电子票
/my/login                手机号验证
/my/orders               我的订单
/my/orders/:id           订单详情与退款
```

### 6.3 活动详情 `/e/:slug`

- 展示封面、名称、主办方、时间、地点、详情和退改说明。
- 售票未开始显示开售时间；已结束、已取消或售罄时禁用报名按钮。
- 地点支持地图跳转；线上活动展示加入方式说明。
- 分享时携带渠道参数并记录来源。

### 6.4 选择票种 `/e/:slug/tickets`

- 展示票种名称、权益、价格、剩余状态和每人限购。
- 数量选择必须满足库存和限购规则。
- 免费票仍需生成零元订单，确保数据口径一致。
- 进入下一步前重新校验票种是否仍可售。

### 6.5 填写报名 `/e/:slug/form`

- 根据活动表单定义动态渲染字段。
- 手机号、邮箱和证件号提供格式校验。
- 实名活动明确提示姓名和证件须与本人一致。
- 勾选服务协议和隐私政策后才能提交。
- 本地保存非敏感草稿；证件号等敏感字段不写浏览器长期存储。

### 6.6 确认订单 `/e/:slug/confirm`

- 展示活动、票种、数量、报名人、价格、优惠和应付金额。
- 创建订单后显示支付倒计时。
- 防止快速重复点击，提交请求携带幂等键。
- 库存不足时返回票种页并刷新剩余状态。

### 6.7 支付与结果

- 调起支付前由服务端创建支付单。
- 用户返回页面后轮询服务端订单状态，不以 URL 参数判断成功。
- 支付成功：展示电子票入口。
- 支付处理中：允许刷新或稍后在“我的订单”查看。
- 支付失败：展示原因和重新支付按钮。
- 订单超时：关闭订单并释放库存。

### 6.8 电子票 `/ticket/:code`

- 展示二维码、票码、参会人、活动、时间地点和状态。
- 截屏可使用，但二维码内容必须是不可预测随机码或签名令牌。
- 已验签展示验签时间；退款或作废展示明显禁用状态。
- 不在二维码中放手机号、证件号等个人信息。

### 6.9 我的订单

1. 输入手机号并获取验证码。
2. 验证通过后签发短期参会人会话。
3. 展示该手机号关联的订单。
4. 订单详情可查看电子票、支付状态和退款进度。
5. 符合规则时可发起退款，提交原因并二次确认。

### 6.10 报名主流程

```text
打开活动 → 选择票种 → 填报名表 → 确认订单
→ 创建报名与订单并锁库存 → 支付 → 支付回调
→ 确认报名 → 生成电子票 → 发送通知
```

异常分支：

- 重复报名：提示已有订单并允许进入订单查询。
- 库存售罄：不创建订单，刷新票种状态。
- 支付超时：关闭订单并释放库存。
- 支付回调重复：通过渠道流水号与幂等键返回既有结果。
- 出票异步失败：订单保持已支付，Worker 重试并触发告警。

## 7. 应用四：现场验签页面

### 7.1 设计原则

- 页面只保留现场必要信息，避免复杂后台导航。
- 验签结果必须大字、高对比，并有声音或震动反馈。
- 连续扫描时防止同一二维码短时间重复提交。
- 网络异常不能误报成功；恢复后同步必须幂等。

### 7.2 页面结构

```text
/login                         工作人员登录
/select                        选择活动与验签点
/scan                          扫码验签
/manual                        手工查询与核验
/result/:recordId              核验结果
/stats                         现场统计
/records                       验签记录
/settings                      设备与反馈设置
```

### 7.3 工作人员登录 `/login`

- 账号密码、手机号验证码或一次性邀请码。
- 登录后显示工作人员姓名和授权范围。
- 无有效授权时禁止进入扫描页，并联系现场负责人。
- 设备更换、异地登录和多次失败记录风险事件。

### 7.4 活动与验签点选择 `/select`

- 仅展示当前工作人员被授权的活动。
- 选择活动后加载可用场次、入口和验签规则。
- 记住最近选择，但每次进入扫描页必须由服务端验证权限。
- 已结束或已停用验签点不可选择。

### 7.5 扫码验签 `/scan`

界面：

- 摄像头取景框、补光灯、摄像头切换。
- 当前活动、验签点和网络状态。
- 手工输入入口、今日已验签数和最近结果。

处理：

1. 识别二维码并解析票码。
2. 本地防抖，短时间内同码只提交一次。
3. 调用 `POST /api/v1/checkins/scan`，携带验签点和幂等键。
4. 服务端事务锁定票券并校验活动、入口、状态和次数。
5. 成功时更新票券并写验签记录。
6. 返回明确结果，页面 1 至 2 秒后恢复连续扫描。

### 7.6 手工核验 `/manual`

- 可按票码、手机号后四位或姓名查询。
- 搜索结果显示脱敏信息和票券状态。
- 验签员确认具体人员后才提交核验。
- 同名多人必须结合手机号后四位或公司区分。

### 7.7 结果状态

| 结果 | 视觉与反馈 | 操作 |
| --- | --- | --- |
| 成功 | 绿色、大勾、成功音/短震动 | 自动返回扫描 |
| 重复 | 橙色、显示首次验签时间与入口 | 查看详情或继续扫描 |
| 已退款/作废 | 红色、明确原因 | 拒绝入场、联系负责人 |
| 跨活动/入口 | 红色、提示正确活动或入口 | 返回扫描 |
| 未找到 | 红色、票码不存在 | 手工查询或重试 |
| 网络错误 | 灰色、不显示成功 | 重试或进入离线队列 |

### 7.8 现场统计 `/stats`

- 已出票、已验签、未验签和验签率。
- 最近 5 分钟验签速度。
- 各入口验签量和失败原因。
- 数据每 10 秒刷新，可手动刷新。
- 普通验签员只看本入口；负责人可看全场。

### 7.9 验签记录 `/records`

- 时间、参会人、票码后四位、入口、操作人、设备和结果。
- 按结果和时间筛选。
- 现场负责人可撤销成功验签，必须填写原因。
- 撤销产生新记录，不覆盖原始记录。

### 7.10 弱网策略

- 请求超时后不得直接显示成功。
- 在线时同步一份当前活动有效票券摘要，不含多余个人信息。
- 离线核验写入本地加密队列，并标记“待同步”。
- 恢复网络后按幂等键顺序同步；冲突进入人工复核。
- MVP 第一版可以先实现“网络失败重试”，完整离线验签列为 P1。

## 9. 数据一致性实现

### 9.1 报名库存事务

```text
BEGIN
  锁定租户统一额度账户；可用额度须 ≥ 1，预留 1 张
  条件更新 ticket_types：sold_count < capacity
  创建 registration
  创建 order
  创建 credit_holds，15 分钟后到期
  写 idempotency_keys
COMMIT
```

若库存或额度条件更新影响 0 行，不得创建报名和订单。预留到期时关闭待支付订单、释放库存和额度；余额查询与新报名应触发清理，正式上线还需定时清理任务。

### 9.2 支付出票事务

```text
BEGIN
  FOR UPDATE 锁定租户额度账户与订单
  判断是否已处理
  已预留额度转为扣减，记录唯一出票流水
  更新订单为 paid
  更新报名为 confirmed
  创建唯一票券
  写 outbox_events(order.paid)
COMMIT
```

生产环境的付费票只能由可信支付渠道回调确认；未接入渠道前拒绝模拟确认。免费票按同一出票额度口径处理。退款成功且满足返还条件时，票券作废、额度返还与唯一返还流水须在同一事务中完成。

### 9.3 验签事务

```text
BEGIN
  校验验签点和人员权限
  FOR UPDATE 锁定票券
  判断 valid / checked_in / void / refunded
  首次有效时更新票券为 checked_in
  写 checkin_records
  写幂等结果
COMMIT
```

## 10. 数据库约束

- 主键统一 UUID。
- 外键按业务删除策略设置 `RESTRICT` 或 `CASCADE`。
- 活动短链接、订单号和票码建立唯一索引。
- `orders.registration_id` 与 `tickets.registration_id` 保持唯一。
- 金额非负，库存容量大于零，售出数不超过容量。
- 高频查询建立 `(tenant_id, event_id, status)` 组合索引。
- 审计和验签记录只追加，不允许业务接口物理删除。
- 租户支付配置按 `tenant_id + channel` 唯一；总部平台支付配置独立存放，不与租户配置共用记录或密钥引用。
- 支付配置保存密文或 Secret Manager 引用，禁止在普通查询、导出和审计详情中返回敏感值；保留配置版本和轮换时间，便于未结订单按原渠道版本处理。
- 支付通知以渠道通知 ID/交易 ID 建唯一约束，退款通知以渠道退款 ID 建唯一约束；相同通知重复到达必须返回幂等结果。
- 服务商模式新增租户进件、特约商户绑定及渠道交易表，建议结构与唯一约束见 13.6；只保存平台服务商密钥引用，不保存租户 API 私钥。数据库迁移须在对应功能实现时单独交付。

## 12. 测试方案

### 12.1 单元测试

- 票种价格、库存和限购规则。
- 租户到期和停用规则。
- 退款资格和金额计算。

### 12.2 API 集成测试

- 租户隔离：A 租户不能读写 B 租户数据。
- 报名幂等：同一幂等键只创建一个订单。
- 并发库存：并发请求不得超卖。
- 支付回调：重复回调只生成一张票。
- 支付凭据隔离：租户只能管理自己的配置；租户接口、总部接口和日志均不能读取明文密钥。
- 支付回调验真：伪造签名、错误商户号、错误金额和错误订单关联均不得确认订单或出票。
- 支付幂等与轮换：重复/乱序通知只处理一次；凭据轮换后已创建支付单仍能查询、退款和对账。
- 服务商进件：跨租户申请、资料访问、重复提交、审核驳回重提、账户验证/签约未完成、AppID 未绑定、交易权限受限均有正确状态；普通客服不能下载完整证件或结算资料。
- 服务商收款：订单绑定的 `sub_mchid` 与租户一致，OpenID 属于使用的 AppID；错误子商户、金额或回调签名不能出票。PC 扫码与手机付款关联同一订单，失效扫码令牌不能创建支付；额度包付款不能改变活动订单。
- 退款回调：重复通知不重复作废票券或返还额度，失败退款不改变订单实付状态。
- 验签并发：同一票并发扫描只能一次成功。
- 总部审计：重命名、期限和状态变化均有日志。

### 12.3 E2E 测试

1. 总部登录并开通租户。
2. 租户登录并创建活动。
3. 租户管理员进入支付设置提交进件，在微信官方页面完成核验及签约；确认支付权限和 AppID 绑定可用、总部普通客服看不到证件原件或任何密钥。
4. 配置票种与报名表并发布。

9. 总部查看平台指标和审计日志。

### 13.4 注册公众号/小程序并获取 AppID

现有参会人入口是微信扫码打开网页，首期选用平台企业主体的**认证服务号**承载网页授权和 JSAPI 支付；普通订阅号、仅取得 AppID 或只注册小程序，都不视为现有网页支付的接入完成。小程序作为后续独立客户端，使用自己的 AppID、登录与支付流程。注册与 AppID 获取入口见[微信支付 AppID 申请说明](https://pay.wechatpay.cn/doc/v3/partner/4012081990)。

1. 在[微信公众平台](https://mp.weixin.qq.com/)注册服务号，提交平台企业主体及管理员资料，完成需要的微信认证；在开发设置中记录 AppID，AppSecret 仅由服务端密钥系统保管。
2. 配置网页授权域名；使用 JSSDK 时配置 JS 接口安全域名，业务域名按实际功能配置。按后台要求部署域名校验文件，准确覆盖实际手机收银台和 OAuth 回调域名。
3. 将服务号 AppID 与平台服务商商户号建立官方绑定，开通对应支付产品；按实际付款路径配置 JSAPI 支付授权目录。公众号域名配置、商户 AppID 绑定和支付授权目录是三个独立步骤。
4. 网页通过微信 OAuth 获取对应公众号下的 OpenID，授权 `state` 与服务端会话和待付订单绑定；回跳地址采用白名单，微信返回的 `code` 只在服务端兑换，不以手机号或前端传入值推算 OpenID。授权域名与 OpenID 对应关系见[微信 JSAPI 常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4012791869)。
5. 后续小程序在公众平台另行注册，按经营类目完成认证、资质和备案，获取独立 AppID，配置 HTTPS 服务器域名后发布。登录使用小程序 `wx.login` 的 code 在服务端兑换身份，付款使用 `wx.requestPayment`；不能直接复用公众号 OpenID。注册入口见[小程序注册指引](https://kf.qq.com/faq/170109iQBJ3Q170109JbQfiu.html)。

| 场景 | 应用标识/用户身份 | 付款方式 |
| --- | --- | --- |
| 参会人微信内打开报名网页 | 平台认证服务号 AppID / 该 AppID 下 OpenID | 微信支付服务商 JSAPI，收款人为租户特约商户 |
| 租户在 PC 购买额度包 | PC 创建订单后，微信扫码打开平台手机收银台；获取绑定汇付商户的服务号下 OpenID | 保持 4.8 的汇付斗拱 `T_JSAPI`，收款人为平台额度销售商户 |
| 后续小程序报名 | 小程序独立 AppID / 小程序 OpenID | 获批的小程序支付，收款人为租户特约商户 |
| 微信外浏览器或桌面浏览器 | 不具备当前 JSAPI 调起环境 | 展示微信扫码继续付款入口；后续 Native/H5 需另行申请和设计，不自动替换 JSAPI |

`AppID` 是应用标识，`mchid` 是微信商户号，汇付 `sys_id`/`huifu_id`/`product_id` 是汇付渠道标识，三者不能相互替代。默认使用平台服务号承载租户网页支付，租户无须逐一注册公众号；如租户使用自有公众号/小程序，须另行验证 AppID 的绑定、授权及应用权限。

### 13.5 平台成为微信支付服务商

选定路线：EventVivid 运营企业直接申请微信支付**普通服务商**，为租户提供技术接入及特约商户进件。普通服务商目前允许企业、政府机关、事业单位、社会组织申请，个人及个体工商户不在该服务商主体范围内；个人开发者要走本方案，应先设立符合条件的企业主体。租户作为特约商户可支持的主体与平台服务商主体要求不同，不混用。申请条件见[微信合作伙伴接入指引](https://kf.qq.com/faq/161220iqeAfA1612202yeURB.html)。

实施前将多租户活动页面、报名售票、收款主体和平台收费方式提交微信支付确认：是否适用普通服务商技术服务模式，或被认定须使用平台收付通等产品。普通特约商户进件接口不适用于电商平台模式；若审核要求平台收付通，应先修订商户模型和结算方案，不能复用普通服务商进件。两种产品切换也不能假设已有子商户自动迁移。参见[特约商户产品适用范围](https://pay.wechatpay.cn/doc/v3/partner/4012062365)及[平台收付通接入要求](https://pay.wechatpay.cn/doc/v3/partner/4012086921)。

1. 准备企业营业执照、法定代表人证件、联系人、客服电话及审核需要的业务说明，在微信支付合作伙伴平台申请服务商，按官方页面完成验证和签约。
2. 获批后取得 `sp_mchid`，绑定认证服务号 `sp_appid`，申请所需进件、JSAPI 及后续小程序支付权限；取得商户号不代表所有产品都已开通。
3. 服务端准备 API 证书序列号、签名私钥、APIv3 密钥、微信支付公钥及公钥 ID（或按接口要求使用有效平台证书），完成请求签名、响应/通知验签与敏感字段加密；与汇付渠道密钥独立管理。
4. 校验服务商权限、AppID 绑定、授权域名、支付目录与公网通知，完成指定租户的进件、付款、查单、退款和账单验收后开放。

资金路径：

```text
租户购买额度包 → 汇付斗拱平台额度销售商户 → 平台结算账户 → 确认成功后增加该租户额度
参会人购买活动票 → 微信支付（EventVivid 服务商代发交易，指定租户 sub_mchid）→ 租户结算账户 → 确认成功后出票
```

微信服务商号本身不作为普通收款商户接收报名款。平台电子票额度销售继续使用现有汇付方案，不因申请微信服务商而替换；既有汇付渠道商编号也不等于 EventVivid 已获得自己的微信服务商号。首期不对活动交易抽佣、不做平台代收后人工转账，平台服务费通过独立额度订单收取。微信服务商资金与身份边界见[官方接入模式说明](https://pay.wechatpay.cn/doc/v3/merchant/4012068443)。

### 13.6 租户进件开通微信特约商户

租户管理员在 `/settings/payment` 发起开通，平台服务端以服务商身份提交，微信审核并由租户本人完成必要验证和签约。总部可协助处理驳回，不能代签或手工伪造获批状态。企业、个体工商户等主体先走普通特约商户方案；无营业执照的小微商户不走此普通接口，只有另行获批对应进件权限、满足经营场景要求后才开放。流程依据见[官方进件准备](https://pay.wechatpay.cn/doc/v3/partner/4012062375)及[特约商户提交接口](https://pay.wechatpay.cn/doc/v3/partner/4012719997)。

- 默认使用平台服务号的获批经营场景；进件成功后仍核查 JSAPI 产品授权、AppID 关联和支付目录。支持租户自有 AppID 时另行验证，不接受前端任意指定收款商户。
- 状态页展示微信返回的申请进度、驳回字段、待核验/签约事项和商户号脱敏值。获取官方签约链接并转为二维码，由指定超级管理员微信扫码核对、验证和签约；链接有效期和操作步骤采用官方实时结果。
- 开通成功页展示租户收款主体、结算账户尾号、渠道及交易权限。修改结算账户走微信官方变更与核验流程，不能仅修改平台数据库即宣称变更成功。

#### 状态与一致性

本地草稿为 `draft`；提交后保存微信原始申请状态、申请编号、查询时间、驳回详情和业务请求编号，映射为“审核中、已驳回、待账户验证、待签约、已完成、已冻结”等用户状态。官方状态枚举与后续操作以接口返回为准，不将所有申请硬编码为同一串行流程。

支付可用状态单独计算：官方进件完成 + 正确的租户 `sub_mchid` + AppID 绑定/授权完成 + 对应交易权限正常。不能仅凭获得商户号或总部点击“启用”允许付费交易。重复提交复用业务请求编号；服务端周期查询申请状态，超时或网络错误保留已有申请，不重复开新商户。关闭租户渠道只阻止新支付，保留未结订单查单、退款及通知能力。

#### 拟新增接口（均为规划，尚未实现）

以下业务路径以 `/api/v1` 为前缀；租户接口从已验证会话获取 `tenant_id`。

| 方法 | 业务路径 | 功能 |
| --- | --- | --- |

| POST | `/tenant/payment/onboarding/materials` | 私有资料上传，返回内部资料引用 |

#### 数据、安全和审计

| 建议数据表 | 关键记录与约束 |
| --- | --- |
| `tenant_payment_applyments` | `tenant_id`、渠道、唯一业务请求编号、官方申请编号、资料版本、原始/映射状态、驳回详情、签约状态及查询时间；同租户同渠道限制一个活跃申请 |
| `tenant_payment_merchants` | `tenant_id`、渠道、`sp_mchid`、`sub_mchid`、采用的 AppID、绑定/授权状态、交易能力、配置版本；`tenant_id + channel` 唯一，同渠道/服务商下 `sub_mchid` 唯一绑定租户 |
| `payment_materials` | 资料归属、对象存储私有引用、微信 MediaID、用途、权限与保留期限；对外只返回业务引用或短期授权链接 |
| `payment_transactions` | 业务类型（活动票/额度包）、业务订单、租户、渠道、收款商户及 AppID 快照、金额、渠道流水、处理状态；渠道交易号与订单支付尝试建立防重复约束 |

- 身份证、银行账号、联系方式和原始资料使用私有存储及字段加密；向微信提交时按官方规则使用微信支付公钥/有效平台证书加密敏感字段，不能把 APIv3 密钥当作请求签名私钥。
- 租户仅访问本租户资料，普通客服只看脱敏状态；必要原件访问授予专门进件人员并记录原因、对象和操作，不在普通日志、审计正文或导出中写原文。
- 进件原件按收集目的、法定义务及渠道约定独立设置最小保留期限，到期清理；不套用活动结束后 6 个月的数据留存规则。租户取消申请时按处理阶段与必要保留义务处理资料。
- 服务商及公众号凭据用 Secret Manager 引用，密钥轮换保留在途交易所需版本；交易订单固定当时收款商户快照，商户变更不能将旧订单切换到另一个租户账户。

### 13.7 服务商 JSAPI 报名收款与 PC 额度购买

#### 租户活动报名

1. 参会人选付费票并提交，服务端以原子事务锁库存和电子票额度，创建本租户订单；订单页显示活动、票种、金额、主办方和剩余付款时间。
2. 点击微信支付时检查订单仍有效、收款权限可用。未开通时提示“主办方尚未开通微信支付，请联系主办方”，保持待支付并按原有到期策略释放资源；不把付款配置检查移回票种选择阶段。
3. 微信内网页取得对应 AppID 下用户身份，服务端按订单租户选择商户，调用 `POST /v3/pay/partner/transactions/jsapi`。默认填写平台 `sp_appid`、`sp_mchid`、租户 `sub_mchid` 及 `payer.sp_openid`；使用已绑定租户应用时按官方组合传 `sub_appid` 与 `payer.sub_openid`，下单、授权及前端调起 AppID 必须匹配。参见[服务商 JSAPI 下单](https://pay.wechatpay.cn/doc/v3/partner/4012738519)。
4. 服务端生成短期有效的调起参数，微信网页用 `WeixinJSBridge` 调起收银台。小程序版本使用相应小程序登录与调起流程，不能在 web-view 内照搬网页 JSAPI。签名参数与 AppID 规则见[JSAPI 调起支付](https://pay.wechatpay.cn/doc/v3/partner/4012090156)。
5. 支付通知验签、解密并核对服务商/子商户、订单、金额和币种；通知成功或可信查单确认成功后，按 9.2 幂等确认订单、消耗额度并出票。浏览器取消/超时不直接认定最终支付失败，先查单；重复付款点击不产生多笔实际扣款。
6. 订单到期先处理关单与查单竞态；已付不可直接释放库存和额度。已关闭订单发生迟到成功通知时进入补偿及必要退款处理，不静默丢弃资金结果。退款沿原交易渠道、原租户商户发起，以回调/查单确认终态后按规则作废票券和返还额度；账单逐租户核对。

拟新增业务接口：`POST /orders/:orderId/wechat-payments`（取支付参数）、`GET /orders/:orderId/payment-status`（查本订单状态）、`POST /payment-notify/wechat/activities`（渠道签名验证，不使用租户 JWT）。公开报名支付使用限定该订单的短期访问令牌/受验证会话；不得只凭可枚举订单号获取票券、手机号或授权支付。金额与收款账户完全由服务端确定。

#### PC 购买额度包

保留 100/500/2000 张商品和汇付 `T_JSAPI`：PC 选择额度包 → 服务端生成本租户额度订单 → 展示订单金额与微信扫码付款入口 → 手机收银台授权并付款 → PC 查询成功后刷新额度。跨端入口采用短期不可猜测的订单令牌，只授予该订单付款能力，不在二维码中包含管理员登录 Token；手机不需要获得 PC 后台登录权限，也不能修改商品、金额或归属租户。

额度订单独立使用汇付商户/渠道适配层、验签规则及通知地址；不调用活动收款的 `sub_mchid`。付款成功记入统一额度余额，重复通知不重复充值。手机支付授权 AppID 必须与汇付商户的获批配置相符，不能直接把微信服务商参数套入汇付请求。正式环境未完成签名、授权、通知和查单闭环时继续展示未开放状态。

### 13.8 实施顺序与上线验收

| 阶段 | 交付与验收条件 |
| --- | --- |
| 1. 主体与域名 | 设立符合服务商条件的运营企业，准备实名域名和大陆接入备案；确认整个平台的适用许可要求及微信业务分类 |
| 2. 微信应用 | 认证服务号、AppID/Secret 托管、授权域名、HTTPS 和校验文件就绪；小程序按后续交付另行注册、备案与审核 |
| 3. 平台支付身份 | 普通服务商申请获批、产品权限和 AppID 绑定完成；汇付平台额度销售商户单独完成配置 |
| 4. 租户进件 | 开通表单、私有资料上传、幂等提交、状态查询、官方验证/签约入口及总部授权协助；实际租户获批并核查可交易权限 |
| 5. 交易闭环 | 微信内付费报名、PC 扫码购买额度、查单补偿、支付通知、出票/充值、关单、退款及账单对账分别验收 |
| 6. 发布运行 | 真实收款主体和结算账户核对通过；重复/伪造通知、跨租户访问、OpenID 错配、订单到期竞态及商户停用场景验收；启用告警和客服处理流程 |

第三方审核、产品开通和备案由实际运营主体办理，平台不能承诺注册后自动获批。研发按上述门槛分阶段开放能力，所有示例域名及尚未签发的 AppID、服务商号只作为占位，不能填入生产交易。

## 15. Definition of Done

一个功能只有同时满足以下条件才视为完成：

- 产品验收标准明确并通过。
- 前后端接口契约已更新。
- 正常、空、错误、无权限和加载状态完整。
- 单元或集成测试覆盖关键规则。
- 高风险操作有审计，敏感信息不进入日志。
- 数据库迁移可重复执行。
- 已通过 TypeScript 类型检查和生产构建。
- 文档、环境变量示例和部署说明同步更新。
